# 0011.1 Live Chat & Collaborative Chess Security Hardening Implementation Roadmap

<callout icon="doodle/misc/trophy">**Status:** Completed · **Owner:** Sam · **Created:** 2026-10-09 · **Completed:** 2026-10-11</callout>

This roadmap defines the sequential execution phases and verification checkpoints for implementing the security remediations, KV write shielding, and quota preservation controls detailed in [0011 Live Chat & Collaborative Chess Security Hardening Specification](0011-live-chat-and-chess-security-hardening-specification.md).

## 1. Roadmap Overview

The plan is divided into 7 sequential phases. Work begins by plugging the critical KV write firehose on crop telemetry (Phase 1) and cutting the self-inflicted polling request drain (Phase 2–3), proceeds to write-path security hardening and session integrity (Phases 4–6), and concludes with regression testing and documentation (Phase 7).

│ Firehose (crop/usage.ts)│     │ Drain (ChessWidget.tsx) │     │ (GET State & Archive)   │
└─────────────────────────┘     └─────────────────────────┘     └─────────────────────────┘
                                                                             │

│ Phase 6: KV Whitelist   │ <── │ Phase 5: Move & Reset   │ <── │ Phase 4: Cryptographic  │
│ & Room Flood Controls   │     │ Turnstile Enforcement   │     │ Session Secret Guard    │

             ▼

## 2. Phased Checkpoints

### Phase 1: Plug the KV Write Firehose on Crop Telemetry

Eliminate unauthenticated KV writes on `CHAT_KV` to protect the daily 1,000-write quota.

- [x] Import `isOriginAllowed` and `checkRateLimit` from [`src/lib/rateLimit.ts`](../../src/lib/rateLimit.ts) into [`src/pages/api/crop/usage.ts`](../../src/pages/api/crop/usage.ts).
- [x] Add `isOriginAllowed(request)` check at the entry of `POST /api/crop/usage`: reject external unapproved origins with HTTP 403 before touching storage or runtime bindings.
- [x] Delete `isRateLimited(kv, ip)` function and eliminate KV reads and writes (`crop:rl:${ip}`) entirely.
- [x] Enforce rate limiting via in-memory `checkRateLimit({ key: \`crop:usage:\${ip}\`, maxRequests: 30, windowMs: 3600_000 })` ($0 cost, 0 KV reads, 0 KV writes).
- [x] Remove `await kv.put(\`crop:usage:\${id}\`, ...)` per-event archival write, reducing telemetry KV writes to **strictly 0**.
- [x] **Verification Check**: Run `npx pnpm run format`, `npx pnpm run lint`, `npx pnpm run check`, and `npx pnpm run build`.

---

### Phase 2: Client Polling Lifecycle Optimization & Tab-Visibility Guard

Stop idle browser tabs from consuming Cloudflare Workers request quotas.

- [x] Add `visibilitychange` listener in [`src/components/chess/ChessWidget.tsx`](../../src/components/chess/ChessWidget.tsx): suspend polling when `document.hidden === true`.
- [x] Resume polling and trigger an immediate state fetch when `document.hidden` becomes `false`.
- [x] Increase steady-state chess polling interval from 3,000ms to **5,000ms** (40% baseline reduction).
- [x] Ensure polling interval is cleanly torn down on unmount (`clearInterval`).
- [x] Forward `If-None-Match` header in `fetchState()` containing the last known `version` ETag.
- [x] Handle HTTP 304 response in `ChessWidget.tsx` by bailing out of re-renders and retaining current state.
- [x] **Verification Check**: Run `npx pnpm run format`, `npx pnpm run lint`, `npx pnpm run check`, and `npx pnpm run build`.

---

### Phase 3: HTTP ETag / 304 Not Modified & Isolate Caching for Chess Read Endpoints

Convert static board polls into 0-cost 304 responses and shield Cloudflare D1.

- [x] In [`src/pages/api/chess/state.ts`](../../src/pages/api/chess/state.ts), generate weak ETag header from game version: `W/"chess-v${game.version}"`.
- [x] Evaluate `If-None-Match` header: if matching, immediately return **HTTP 304 Not Modified** with empty body, skipping arbiter re-instantiation and D1 query.
- [x] Add a short-lived in-memory isolate cache (`STATE_CACHE_TTL_MS = 2000`) in `state.ts` to collapse rapid concurrent visitor polls.
- [x] In [`src/pages/api/chess/archive.ts`](../../src/pages/api/chess/archive.ts), implement isolate cache (`ARCHIVE_CACHE_TTL_MS = 2000`) and edge rate limiting (30 req / 60s per IP).
- [x] **Verification Check**: Run `npx pnpm run format`, `npx pnpm run lint`, `npx pnpm run check`, and `npx pnpm run build`.

---

### Phase 4: Cryptographic Session Secret Resolution & Fail-Closed Enforcement

Eliminate static secret fallback in chess session management and bind runtime secrets.

- [x] Add `CHESS_SESSION_SECRET?: string` declaration to `App.Locals` in [`src/env.d.ts`](../../src/env.d.ts).
- [x] Implement `getSessionSecret(locals?: App.Locals): Promise<string | null>` in [`src/lib/chess/session.ts`](../../src/lib/chess/session.ts) using `getWorkersEnv()`, `locals`, and fallback to `TURNSTILE_SECRET`.
- [x] Update `signSession()` and `verifySession()` in [`src/lib/chess/session.ts`](../../src/lib/chess/session.ts) to accept optional `locals` or secret string.
- [x] Enforce fail-closed verification: reject session tokens if no secret can be resolved outside dev/test environments.
- [x] Pass `locals` from API routes (`state.ts`, `move.ts`, `reset.ts`) to `verifySession()` and `signSession()`.
- [x] **Verification Check**: Run `npx pnpm run format`, `npx pnpm run lint`, `npx pnpm run check`, and `npx pnpm run build`.

---

### Phase 5: Fail-Closed Turnstile Bot Gate on Chess Moves & Reset Protection

Ensure chess write surfaces strictly require verified human sessions.

- [x] Refactor Turnstile pass verification in [`src/pages/api/chess/move.ts`](../../src/pages/api/chess/move.ts) to fail closed: return HTTP 403 or 503 if secret is missing or pass is invalid in production.
- [x] Import `verifyChatPass`, `getTurnstileSecret`, and `getCookie` into [`src/pages/api/chess/reset.ts`](../../src/pages/api/chess/reset.ts).
- [x] Add mandatory `chat_pass` verification gate to [`src/pages/api/chess/reset.ts`](../../src/pages/api/chess/reset.ts) before processing match reset and archiving.
- [x] Update client-side [`src/components/chess/ChessWidget.tsx`](../../src/components/chess/ChessWidget.tsx) in `handleResetMatch()` to forward `x-chat-pass` header from `sessionStorage`.
- [x] Handle `requireTurnstile` response in `ChessWidget` on reset failure by triggering pass re-verification gate.
- [x] **Verification Check**: Run `npx pnpm run format`, `npx pnpm run lint`, `npx pnpm run check`, and `npx pnpm run build`.

---

### Phase 6: KV Payload Whitelisting & Fair Chat Flood Controls

Protect Cloudflare KV quota and eliminate silent room-wide muting.

- [x] Define constant `ALLOWED_AVATARS` set in [`src/pages/api/chat/send.ts`](../../src/pages/api/chat/send.ts) (`knight`, `rook`, `bishop`, `pawn`, `king`, `queen`).
- [x] Validate and sanitize incoming `avatar` parameter, falling back to default `"knight"` for unrecognized or oversized strings.
- [x] Increase `GLOBAL_MAX_PER_MINUTE` threshold in [`src/pages/api/chat/messages.ts`](../../src/pages/api/chat/messages.ts) from 15 to 45 messages / minute.
- [x] Maintain strict per-IP rate limits (5 msgs / 60s per IP with 3s cooldown) to ensure spam bots are throttled individually without impacting legitimate users.
- [x] **Verification Check**: Run `npx pnpm run format`, `npx pnpm run lint`, `npx pnpm run check`, and `npx pnpm run build`.
