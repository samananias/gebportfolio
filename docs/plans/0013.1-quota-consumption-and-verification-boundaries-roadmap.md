# 0013.1 Quota Consumption & Verification Boundaries Hardening Roadmap

<callout icon="doodle/misc/trophy">**Status:** Active · **Owner:** Sam & Antigravity · **Created:** 2026-10-12</callout>

This roadmap defines the sequential execution phases and verification checkpoints for implementing the multi-tier edge caching, atomic D1 rate limiting, quota protection, and bypass isolation controls detailed in [0013 Quota Consumption & Verification Boundaries Hardening Specification](0013-quota-consumption-and-verification-boundaries-specification.md).

---

## 1. Roadmap Overview

The execution sequence begins with the highest-risk live scraping vector on contributions (Phase 1), establishes atomic D1 rate limiting and Brevo email budget guards on the contact route (Phase 2), isolates test bypasses to local hosts (Phase 3), addresses KV archive hygiene and documentation accuracy (Phase 4), adds cheap rate guards to polling endpoints (Phase 5), and finishes with end-to-end quality validation (Phase 6).

```
┌─────────────────────────────────┐     ┌─────────────────────────────────┐
│ Phase 1 (P0): Contributions     │ ──> │ Phase 2 (P0): D1 Rate Limits    │
│ Edge Cache API + IP Throttling  │     │ Atomic Buckets & Brevo Caps     │
└─────────────────────────────────┘     └─────────────────────────────────┘
                                                       │
                                                       ▼
┌─────────────────────────────────┐     ┌─────────────────────────────────┐
│ Phase 4 (P1): Hygiene & Docs    │ <── │ Phase 3 (P1): Localhost Guard   │
│ KV TTL + ADR 0011/0013 + Logs   │     │ Isolate E2E & Pass Bypasses     │
└─────────────────────────────────┘     └─────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐     ┌─────────────────────────────────┐
│ Phase 5 (P2): Read Polling      │ ──> │ Phase 6: Quality Gates & Tests  │
│ Guards on Messages & Chess      │     │ E2E, Unit Tests & Post-Deploy   │
└─────────────────────────────────┘     └─────────────────────────────────┘
```

### Phase 2 (P0): Atomic Rate Limiting & Global Caps via D1 (Fixes F1, F2)

Replace the race-prone KV counter on `/api/contact` with atomic serialized D1 statements and enforce site-wide quotas.

- [x] Create `migrations/0002_add_throttle_buckets.sql`:
  ```sql
  CREATE TABLE IF NOT EXISTS throttle (
    bucket       TEXT PRIMARY KEY,
    window_start INTEGER NOT NULL,
    count        INTEGER NOT NULL
  );
  ```
- [x] Create `src/lib/dbThrottle.ts`:
  - Implement `consumeThrottle(db, bucket, max, windowSeconds)` using atomic SQL:
    ```sql
    INSERT INTO throttle (bucket, window_start, count) VALUES (?1, ?2, 1)
    ON CONFLICT(bucket) DO UPDATE SET
      count        = CASE WHEN ?2 - window_start >= ?3 THEN 1 ELSE count + 1 END,
      window_start = CASE WHEN ?2 - window_start >= ?3 THEN ?2 ELSE window_start END
    RETURNING count, window_start;
    ```
  - Calculate `retryAfterSec = Math.max(1, (window_start + windowSeconds) - nowSec)`.
  - Soft-fail to `{ allowed: true, count: 1, retryAfterSec: 0 }` if `db` is unavailable.
  - Add hourly background cleanup query for stale buckets (`window_start < now - 172800`).
- [x] In [`src/pages/api/contact.ts`](../../src/pages/api/contact.ts):
  - Add emergency kill switch check `CONTACT_LOCKED === "1" || CONTACT_LOCKED === "true"` returning `HTTP 503` with `Retry-After: 300`.
  - Replace KV `isRateLimited` with D1 bucket `contact:ip:<ip>` (3 / 3600s).
  - Add global hourly backstop bucket `contact:global:hour` (12 / 3600s, configurable via `CONTACT_HOURLY_MAX`).
  - Add daily email budget bucket `contact:email:day` (200 / 86400s, configurable via `CONTACT_DAILY_EMAIL_BUDGET`).
  - If daily email budget exhausted: skip Brevo, call `archiveToInbox(..., delivered: false)`, log warning, and return honest `HTTP 502` guidance.
- [x] **Verification Check:**
  - Apply local migration: `cmd /c "npx wrangler d1 migrations apply DB --local"`
  - Verify `tests/e2e/contact.spec.ts` passes without regressions.
