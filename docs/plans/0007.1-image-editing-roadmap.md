## Phase 1 — Freely movable image (Feature 1) `[COMPLETED]`

Replace the roaming crop box with a fixed centered frame; the photo pans
underneath it. Touch the export contract (`600px` for `2x2`, `300px` for
`1x1`) only by deriving the box differently, never by changing targets.

- [x] Add a pure, DOM-free clamp helper (proposed
      `src/lib/crop/geometry.ts`): given image size, frame size/offset, and
      zoom, return the clamped pan offset so the frame always lies fully
      inside the image (coverage invariant). Unit-testable without a browser.
- [x] Replace `box` state in `src/components/islands/CropStudio.tsx` with
      a fixed centered frame plus pan-offset state in natural image pixels;
      drag maps screen delta through the shared fit transform
      (`1 / fitScale`), sign-inverted (dragging right moves the image right).
- [x] Update `draw()`: fixed frame rect from stage center; image drawn at
      pan offset; keep the single shared fit transform so preview and export
      agree. Set `touch-action: none` on the pan surface only.
- [x] Update interactions: pointer events (plus `setPointerCapture`) and
      keyboard (`Arrow` = 4 px, `Shift+Arrow` = 20 px) move the image;
      re-clamp on every pan, zoom, preset switch, and resize.
- [x] Update `handleExport()`: derive the sampled box from pan offset
      plus frame size; keep the existing `drawImage(box to target)` geometry.
- **Checkpoint** (verified): `format`, `lint`, `check`, `build` pass;
  extended `tests/e2e/crop-studio.spec.ts` passes 4/4 (chromium) — keyboard
  pan and drag each change the export `href` bytes.

## Phase 2 — Face placement guide (Feature 2) `[COMPLETED]`

Preview-only overlay inside the fixed frame. Depends on Phase 1 (the
frame no longer roams, so guide proportions are stable).

- [x] Preview-only overlay pass in `draw()` (canvas strokes): head oval

- [x] Proportions from `faceGuideForPreset()` in `src/lib/crop/geometry.ts`

- [x] Labelled `role="switch"` toggle (default on, per page session)
      beside the zoom control, plus helper copy ("Guide only — it never
      exports.") doubling as the text alternative.
- [x] Export path untouched: `handleExport()` draws source pixels only.
- **Checkpoint**: `format`, `lint`, `check` (0 errors, `check-links`
  SUCCESS), `build`, `test:e2e` crop-studio 5/5 (chromium), `test:a11y`

## Phase 3 — Dedicated background-removal page (Feature 3) `[COMPLETED]`

New removal-only route reusing the existing on-device pipeline. Depends
on nothing from Phases 1–2 (parallelizable), but lands last so shared
extraction is informed by the final `CropStudio` shape.

- [x] Extract the shared removal logic from `CropStudio.tsx` (lazy
      `@imgly` import, fetch progress, cutout object-URL lifecycle with
      revoke-on-replace, metadata-only `POST /api/crop/usage`, failure copy)
      into a shared hook or helper both pages import — no duplication.
- [x] Add the new route (proposed `/remove-background`): upload, remove,
      original-versus-result compare (side by side or before/after toggle)
      with a checkerboard behind the result, and a transparency-preserving
      PNG download. No crop frame, guide, preset radios, zoom, or size
      controls may appear on this page. Any JPEG fallback is labelled as
      flattening transparency.
- [x] Apply the same upload guards (`validateFileMeta`: JPEG/PNG, 8 MB,
      4000 px) and non-fatal failure pattern as `/crop`; keep the on-device
      honesty copy (`REMOVAL_MODEL`).
- [x] Link both ways with `/crop` and list the page in the Lab content
      (`id-photo-studio.md` demo links or a sibling entry).
- **Checkpoint** (verified): `format`, `lint`, `check` (0 errors,
  `check-links` SUCCESS), `build` pass; `tests/e2e/remove-background.spec.ts`
  (chromium, model mocked) passes — alpha-intact PNG download, upload-guard
  rejections, graceful degradation when removal fails, and no crop
  selectors on the page; `test:a11y` chromium 8/8 including the new route.

## Phase 5 — Independent image zoom (Feature 1 amendment) `[COMPLETED]`

Amends Phase 1: post-ship use showed the zoom slider scaled the shared
fit transform, magnifying the frame and guide together — a view
magnifier with no effect on the exported composition.

- [x] Pure helpers in `src/lib/crop/geometry.ts`: `sampledSizeForZoom`
      (zoom 1 = cover fit; sampled side = `minSide / zoom`) and
      `repanForZoom` (center-anchored re-clamp on zoom change).
- [x] `draw()`: zoom applies to the image only; the frame is pinned to
      the stage (hairline inset border replaces the scaling rect and dim
      bars) and the guide anchors to the stage.
- [x] Zoom slider relabelled `Image zoom`, range `[1, 4]`; `box.size`
      re-derived and re-clamped on every change so pointer, keyboard, and
      export paths stay untouched.
- [x] Quality: `imageSmoothingQuality: "high"` in preview, export, and
      `fitWithinCap`; `fitWithinCap` emits a blob URL instead of a data
      URL; upscaling past source resolution is allowed with a visible
      softness note.
- **Checkpoint** (verified): `format`, `lint`, `check` (0 errors,
  `check-links` SUCCESS), `build` pass; crop-studio e2e 6/6 (chromium)
  including "image zoom changes the exported framing and flags
  upscaling" (fails on the pre-amendment model).
