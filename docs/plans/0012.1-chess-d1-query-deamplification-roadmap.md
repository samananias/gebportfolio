# 0012.1 Chess D1 Query De-amplification & Multiplayer Hardening Implementation Roadmap

<callout icon="doodle/misc/trophy">**Status:** Active · **Owner:** Sam & Antigravity · **Created:** 2026-10-12</callout>

This roadmap defines the sequential execution phases and verification checkpoints for implementing the D1 query de-amplification, runtime schema detachment, multiplayer cache consistency, and archive idempotency controls detailed in [0012 Chess D1 Query De-amplification & Hardening Specification](0012-chess-d1-query-deamplification-specification.md).

---

## 1. Roadmap Overview

The plan is divided into 5 sequential phases. Work begins by purging the 5-statement runtime DDL preamble from the storage layer (Phase 1), proceeds to archive idempotency and contributor accounting (Phase 2), adds edge rate limiting and origin checks to state reads while preserving cross-isolate multiplayer consistency (Phase 3), introduces client-side game-over polling backoff (Phase 4), and concludes with comprehensive multiplayer concurrency and query budget verification (Phase 5).

```
┌───────────────────────────┐     ┌───────────────────────────┐     ┌───────────────────────────┐
│ Phase 1: Storage Layer    │ ──> │ Phase 2: Archive          │ ──> │ Phase 3: State Route      │
│ Purge DDL from getGame()  │     │ Idempotency & Reset Guard │     │ Edge Rate Limit & Origin  │
└───────────────────────────┘     └───────────────────────────┘     └───────────────────────────┘
                                                                                  │
                                                                                  ▼
┌───────────────────────────┐                                       ┌───────────────────────────┐
│ Phase 5: Concurrency,     │ <──────────────────────────────────── │ Phase 4: Client Polling   │
│ Budget Tests & Validation │                                       │ Backoff on Game Over      │
└───────────────────────────┘                                       └───────────────────────────┘
```

## 2. Phased Checkpoints

### Phase 1: Storage Layer DDL Detachment (The Core De-amplifier)

Eliminate the 5-statement auto-schema preamble executed on every runtime request.

- [x] In [`src/lib/chess/storage.ts`](../../src/lib/chess/storage.ts), remove `ensureD1Tables()` from the runtime path.
- [x] Remove `initSchema()` from `getGame()`, `saveGame()`, and `getArchivedGames()`.
- [x] Refactor `createD1StorageProvider`:
  - `getGame()`: executes single statement `SELECT * FROM game WHERE id = 1`.
  - `saveGame()`: executes single parameterized `UPDATE game SET ... WHERE id = 1 AND version = ?`.
  - `archiveGame()`: executes single parameterized idempotent `INSERT INTO finished_game ...`.
  - `getArchivedGames()`: executes single parameterized `SELECT * FROM finished_game ORDER BY id DESC LIMIT ?`.
- [x] Eliminate all JavaScript string interpolation in SQL statements; verify 100% parameterization with `.bind(...)`.
- [x] **Verification Check**: Run `npx pnpm run lint && npx pnpm run check`.

---

### Phase 2: Archive Idempotency & Contributor Counting Fix

Prevent duplicate finished game archives during concurrent move/reset requests and fix contributor double-counting.

- [x] In [`src/lib/chess/storage.ts`](../../src/lib/chess/storage.ts), update `archiveGame` to use:
  ```sql
  INSERT INTO finished_game (pgn, outcome, contributors, ended_at)
  SELECT ?, ?, ?, ?
  WHERE NOT EXISTS (SELECT 1 FROM finished_game WHERE pgn = ?);
  ```
- [x] In [`src/pages/api/chess/reset.ts`](../../src/pages/api/chess/reset.ts), remove line 147 duplicate addition:
  ```typescript
  allTimeContributors: game.allTimeContributors || 0,
  ```
- [x] In [`src/lib/chess/outcome.ts`](../../src/lib/chess/outcome.ts), add early return if `history.length < 4` to skip redundant move replay while fully preserving threefold repetition and fifty-move rule checks when history is present.
- [x] **Verification Check**: Run `npx pnpm run lint && npx pnpm run check`.

---

### Phase 3: State Route Origin Shielding & Safe Polling Rate Limits

Protect `GET /api/chess/state` from automated scraping without risking stale boards or throttling multi-user LAN players.

- [x] In [`src/pages/api/chess/state.ts`](../../src/pages/api/chess/state.ts), remove local in-memory isolate caching (`STATE_CACHE_TTL_MS = 0`) to guarantee that every isolate reads authoritative state directly from D1, preventing stale 304 responses between players across different Cloudflare Worker instances.
- [x] Import and apply `isOriginAllowed(request)`.
- [x] Import and apply `checkRateLimit({ key: 'chess:state:' + clientIp, maxRequests: 60, windowMs: 60_000 })`.
- [x] Retain ETag generation `W/"chess-v${game.version}"` and evaluate `clientEtag === etag` after the clean single `SELECT`.
- [x] **Verification Check**: Run `npx pnpm run lint && npx pnpm run check`.

---

### Phase 4: Client Polling Lifecycle Optimization on Game Over

Prevent completed matches left open in browser tabs from consuming continuous 5-second polling traffic.

- [x] In [`src/components/chess/ChessWidget.tsx`](../../src/components/chess/ChessWidget.tsx):
  - When `isGameOver` (`gameState?.outcome` is non-null), adjust polling timer to **30,000ms** (or pause).
  - When user resets match or receives a fresh game state, restore active **5,000ms** polling interval.
- [x] **Verification Check**: Run `npx pnpm run lint && npx pnpm run check`.
